# NanoHarness v0.2.245

## Desktop fixes

- On Windows, chats load again when Harness is opened from the Start menu: the app now finds Harness's data folder the same way the engine does, so it can connect to the engine (#230).
- Moving between sessions in a split keeps each pane's own model pick, unsent prompt, attachments and unsaved file edits with that pane (#151).
- Clicking the open session in the sidebar, or picking a pane in Cmd+K, gives input back to that chat from an expanded Host or Files panel (#151).
- Picking a different project from an open chat opens it in a new tab instead of replacing that chat (#151).
- Opening a live chat no longer joins a tab that only shows an archived session (#151).
- Reopening Harness returns each open chat to where you were reading: a chat you had scrolled up reopens at the same message, and one at the bottom keeps following new replies. Each split pane keeps its own position, and positions are saved before an update restarts the app (#237).
- Restart to update checks for the latest release once more before relaunching, so Harness restarts once into the newest verified version instead of into an update that a newer release has already replaced. If that check fails, Harness stays open (#236).
- A subagent that fails shows as failed, with the reason graff gives, or a line saying graff did not report one, in its row, its tab and the saved transcript. A subagent with no recorded outcome reads "Ended" instead of "Done", and a subagent tab that cannot load says why and stops re-checking every two seconds (#238).
- Settings › Appearance › Reduce motion now takes effect: On and Off override your system setting, and System follows it. Settings no longer shows controls that did nothing (the Appshots page, "Pause animations in background" and "Restart Harness" under Screen Recording), has one Back control in every mode and in full screen, draws the backdrop studio once, and names the chat splits "Split chat right/down" in Shortcuts (#242).
- Allow once in Settings → Devices now lets a relayed remote action (a git action, a discard, a file write or a worktree change) through once, for the same device and the same request. Terminal requests offer only Always allow. A refused remote action now says whether remote control is off on the host or that device needs approval there (#245).
- Open file on a workspace file linked in a chat, such as a Markdown file, opens it in Files instead of saying the file type cannot be opened. Local file links offer Copy file path, which copies the plain path, and a file that fails to open names the file and the reason (#247).
- Controls say what they do and appear once. ⌘J toggles the terminal & action runs dock, as its title-bar button and palette entry say, and that button is dimmed with a reason when there are no runs. The title bar's open-tabs button has a list icon and an "Open tabs" tooltip. New project (⇧⌘N or the palette) opens the New project form. Send is dimmed while the draft is empty or the engine is not connected, and a send while disconnected keeps your message and says why. The repeated "+" button, palette entries, project and computer chips and pull-request buttons are gone (#248).
- Previews opened in the in-app browser are reported to graff, so graff can stop a preview server once its last tab closes or Harness quits. A preview opened in your system browser is never reported as unused (#251).
- Views with deeply nested rows lay out faster: each box is measured once per width instead of again at every level above it, so a deep view no longer stalls a frame (#232).
- Failed turns keep their partial replies and failure status after a restart. Completed replies clear the unread badge when you're already viewing the chat.
- Generated pages stay available in compact transcripts, and FYI messages can reach a chat's inbox without queuing a new prompt.
- The Speed picker follows the model's available tiers. If Ultra Fast becomes unavailable and Fast is offered, the next message uses Fast while your saved choice is kept.

## For contributors

- `scripts/heavy-build.sh` runs queued builds first come, first served, can split them into named lanes with several slots, reports a build that holds the queue too long, and shows who holds and who waits with `--status` (#250).
- `docs/agent-driven-tests.md` describes how a feature is built by a test author, an implementer and a breaker, and what its pull request reports (#246).
- The documentation describes the Zig desktop client and the Rust engine instead of the retired GPUI app, and `AGENTS.md` says which repository an issue belongs in (#239).
- The Zen title-bar test now checks the right-aligned lone-chat caption from #225, so the desktop UI tests pass on `main` again (#253).
